# MCP Example: School Chatbot

A small, end-to-end example of the **Model Context Protocol (MCP)**.
A command-line chatbot powered by **Grok** answers questions about students in a MySQL `school` database.
It does this by calling tools exposed by **two MCP servers**: one over **HTTP** and one over **stdio**.

```
You: What marks did student 7 get?
  [tool] get_academic_data({'sl_no': 7})

Assistant: Student 7 (Khalid Al Kaabi) marks:
- English: 72
- Science: 81
- Business Education: 59
- Finance: 43
```

## Architecture

```
                        ┌──────────────────────────┐
                        │      Grok (xAI API)      │
                        │  picks which tool to use │
                        └────────────▲─────────────┘
                                     │ chat + tool calls
                        ┌────────────┴─────────────┐
  you ─── terminal ───▶ │      mcp_client.py       │
                        │   (command-line chatbot) │
                        └──────┬────────────┬──────┘
               HTTP            │            │          stdio
   http://127.0.0.1:8050/mcp   │            │  (client starts it as a child process)
                ┌──────────────▼───┐   ┌────▼─────────────────┐
                │ mcp_server_http  │   │  mcp_server_stdio    │
                │ get_personal_data│   │  query_database      │
                │ get_academic_data│   │  (SELECT only)       │
                └────────┬─────────┘   └─────────┬────────────┘
                         └───────────┬───────────┘
                               ┌─────▼─────┐
                               │   MySQL   │
                               │  school   │
                               └───────────┘
```

**How a question is answered**

1. The client connects to both MCP servers and asks each one for its list of tools.
2. It sends your question and the tool definitions to Grok.
3. Grok decides which tool to call (if any) and with which arguments.
4. The client runs that tool on the server that owns it and sends the result back to Grok.
5. Grok turns the result into a plain-English answer.

## The tools

| Tool | Server | Transport | Input | Returns |
|------|--------|-----------|-------|---------|
| `get_personal_data` | `mcp_server_http.py` | HTTP (streamable-http) | `sl_no` | The student's row from `personal_data` |
| `get_academic_data` | `mcp_server_http.py` | HTTP (streamable-http) | `sl_no` | The student's row from `academic_data` plus `student_name` (joined on `sl_no`) |
| `query_database` | `mcp_server_stdio.py` | stdio | `query` (SQL) | Query results as JSON. Only `SELECT` is allowed. |

The docstring of `query_database` contains the full database schema, so Grok knows how to write
correct SQL for questions like *"Who has the highest marks in finance?"*.

`query_database` is read-only in two ways: it rejects any query that does not start with `SELECT`,
and it runs the query inside a MySQL `READ ONLY` transaction.

## Database

`setup_db.py` creates the `school` database with two tables and fills them with 20 synthetic students.
Most names are Arabic and Gulf names (for example Omar Al Mansoori, Fatima Al Nuaimi and Yousef Al Thani),
alongside a few Indian, Filipino and other names. Each student shares the father's family name;
mothers keep their own family name, as is common in the Gulf.

**personal_data**

| Column | Type |
|--------|------|
| sl_no | INT, primary key |
| student_name | VARCHAR(100) |
| student_dob | DATE |
| mother_name | VARCHAR(100) |
| mother_occupation | VARCHAR(100) |
| father_name | VARCHAR(100) |
| father_occupation | VARCHAR(100) |

**academic_data** (marks are whole numbers from 0 to 100)

| Column | Type |
|--------|------|
| sl_no | INT, primary key, references `personal_data.sl_no` |
| marks_english | INT |
| marks_science | INT |
| marks_business_education | INT |
| marks_finance | INT |

## Project structure

```
mcp_example_school/
├── setup_db.py          # creates the school database and 20 synthetic students
├── db.py                # shared MySQL connection helper (reads .env)
├── mcp_server_http.py   # MCP server over HTTP: get_personal_data, get_academic_data
├── mcp_server_stdio.py  # MCP server over stdio: query_database
├── mcp_client.py        # command-line chatbot using Grok
├── pyproject.toml       # project dependencies (managed by uv)
├── uv.lock              # exact pinned versions, generated by uv
├── .python-version      # Python version uv uses for this project
└── .env                 # your secrets (not committed)
```

## Setup

**Prerequisites:** a running local MySQL server, an xAI API key, and [uv](https://docs.astral.sh/uv/).
uv installs the right Python version for you if it's missing.

Install uv if you don't have it:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh    # macOS / Linux
# or: brew install uv
```

1. Install the dependencies. This creates `.venv` from `pyproject.toml` and `uv.lock`:

   ```bash
   cd mcp_example_school
   uv sync
   ```

2. Create a `.env` file in this folder:

   ```env
   grok_api_key=your-xai-api-key
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=your-mysql-password
   ```

3. Create the database and sample data:

   ```bash
   uv run setup_db.py
   ```

   Running it again resets the tables to the same 20 students.

## Run

You need **two terminals**. `uv run` uses the project's `.venv`, so there's nothing to activate.

**Terminal 1: start the HTTP MCP server**

```bash
uv run mcp_server_http.py
```

It listens on `http://127.0.0.1:8050/mcp`.

**Terminal 2: start the chatbot**

```bash
uv run mcp_client.py
```

The client starts the stdio server (`mcp_server_stdio.py`) for you, using the same Python
interpreter it runs on, so it gets the same `.venv` packages.

Commands inside the chat: `clear` resets the conversation, `exit` or `quit` ends it.

### Things to try

| Question | Tool Grok picks |
|----------|-----------------|
| What are the personal details of student 3? | `get_personal_data` |
| What marks did student 7 get? | `get_academic_data` |
| Who has the highest marks in finance? | `query_database` |

### Adding a dependency

```bash
uv add <package>
```

This updates `pyproject.toml` and `uv.lock` together.

## Model

The client uses `grok-build-0.1`, the cheapest model on the xAI API at the time of writing
($1 per million input tokens, $2 per million output tokens).
xAI's API is OpenAI-compatible, so the client uses the `openai` Python package with
`base_url="https://api.x.ai/v1"`. To use a different model, change `MODEL` in `mcp_client.py`.

## Notes

- The servers use `FastMCP` from the official MCP Python SDK. `pyproject.toml` pins `mcp<2`,
  because MCP SDK 2.x renamed `FastMCP` to `MCPServer`.
- Secrets live only in `.env`, which is listed in `.gitignore`.

## Testing with MCP Inspector

[MCP Inspector](https://github.com/modelcontextprotocol/inspector) is the official browser tool for
listing and calling a server's tools directly, without the chatbot. It needs [Node.js](https://nodejs.org/).

1. Start the HTTP server: `uv run mcp_server_http.py`
2. In another terminal, from this folder, start the Inspector:

   ```bash
   npx @modelcontextprotocol/inspector
   ```

   Open the link it prints (it includes an access token).

**HTTP tools**

- Transport: **Streamable HTTP**
- URL: `http://127.0.0.1:8050/mcp`
- Click **Connect**, open **Tools**, and run `get_academic_data` with `sl_no` = `7`.

**stdio tool**

- Transport: **STDIO**
- Command: `uv`
- Arguments: `run mcp_server_stdio.py`
- Click **Connect**, open **Tools**, and run `query_database` with `SELECT * FROM personal_data LIMIT 3`.

The Inspector starts the stdio server from the folder you launched it in. If you launched it
somewhere else, use the arguments `--directory /path/to/mcp_example_school run mcp_server_stdio.py`.

Prefer the terminal? The Inspector also has a CLI mode:

```bash
npx @modelcontextprotocol/inspector --cli http://127.0.0.1:8050/mcp --transport http \
  --method tools/call --tool-name get_academic_data --tool-arg sl_no=7
```

## Troubleshooting

**`warning: VIRTUAL_ENV=... does not match the project environment path .venv and will be ignored`**

Another virtual environment is active in your terminal. This is harmless: uv ignores it and uses the
project's `.venv`. To get rid of the warning, run `deactivate` first. With uv you never need to
activate an environment yourself.

**`Not Acceptable: Client must accept text/event-stream` when opening `/mcp` in a browser**

This is expected. `/mcp` is for MCP clients, not browsers, so a plain browser request is rejected.
Opening `http://127.0.0.1:8050/` shows a short "server is running" page instead. To test the tools,
run `uv run mcp_client.py`.

**404s like `GET /json/version` in the HTTP server log**

A browser, Chrome DevTools or VS Code is probing the port. The server only serves `/` and `/mcp`, so
other requests get a 404. They are expected and harmless. To check the server is working, run
`uv run mcp_client.py`.

**`address already in use` when starting the HTTP server**

Something else is already using port 8050. Find it with:

```bash
lsof -i :8050
```

Stop that process, or pick another port: change `port=8050` in `mcp_server_http.py` and
`HTTP_SERVER_URL` in `mcp_client.py` to match.
